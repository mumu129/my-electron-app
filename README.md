## 一句话定位

**一个专门跑"加密业务流"的本地工作台**：从 HAR 导入请求 → 按业务切分成请求组 → 用标签声明加密规则 → 用状态机自动跑完整条业务流程 → 并发跑多个组/项目 → 结果沉淀成可复用的配置。

**不是**：抓包工具、不是 Burp 替代品、不是通用 HTTP 客户端、不是漏洞扫描器。

---

## 核心工作流

```
抓包(外部工具) → 导入 HAR → 按业务切分请求组 → 配标签加密规则
             → 执行组(自动处理依赖/副组条件) → 二进制/文本原样发送
             → 多个组并发跑 → 结果沉淀
```

## 我真正要实现的东西（关键，防止跑偏）

### 1. 加密业务流的"状态机执行"
- 一个请求组有**主组**（顺序执行）+ **副组**（条件触发）
- 主组产出变量（如 `level`），副组按 `[min, max)` 区间匹配执行
- 区间有 `success / failed / none` 状态，失败重试到 `maxRetries` 次标记死局
- 这就是**业务流的状态机**，不是单请求的重放

### 2. 标签引擎（Hackvertor 风格）
- 六种标签类型：`enc`（加密，每次重算） / `dec`（解密） / `op`（累积运算，写回原文） / `var`（提取变量） / `env`（引用全局变量） / `script`（主进程 Node 脚本）
- 语法：`<@类型:算法名:参数1=值1,参数2=值2>内容</@类型:算法名>`
- **op 标签累积写回**：5 → 6 → 7 → 8，每轮执行看到的都是最新值
- **enc/dec 每次重算**：不写回，保证每次发送用的都是最新计算结果

### 3. 二进制原样发送
- **body 整个就是一个二进制标签时 → 主进程按字节发送**（`request.write(Buffer.from(bytes))`）
- 服务器收到的就是**原始二进制**，没有 base64、没有字符串转换
- **嵌套场景**（内层二进制被外层标签包裹、JSON 内嵌）→ 只能 base64 转字符串嵌入（HTTP 语义限制，不是 bug）
- 复合操作用**一个 script 标签**在内部完成，返回 Buffer 直接二进制发送

### 4. 并发执行 + 跨项目预案
- **引擎级支持任意组并发**（同项目、跨项目都行）
- 每个任务独立：自己的 proxy、自己的 `ctx.vars`、自己的副组状态、自己的 intervalSec
- **执行日志面板**（顶栏按钮 + 右侧 Drawer）统一查看所有运行中任务，按项目分组
- **全局预案**（项目设置页）：跨项目勾选组 + 设间隔，一键批量启动
- **项目级预案**：单项目内的批量启动配置

### 5. env 全局常量管理（解决真实痛点）
- **痛点**：token 每次都从 HAR 里拿，之前必须重新导入整条请求（因为 HAR 里是密文，无法 diff 保留标签）
- **解法**：env 是主体，每个 env 有自己的**提取规则**（`urlMatch + source + 可选解密 + 正则`）
- 组内请求用 `<@env:TOKEN>` 引用，token 变了点「刷新」自动从 HAR 提取 → 填入输入框 → 用户确认
- **env 多套环境集**：账号 A / 账号 B，一键切换整体值

## 设计意图（**不是 bug**，不要"修复"）

1. **op 标签输出二进制会被跳过并 console.warn** — op 语义是"可字符串化的累积运算"，二进制请用 enc
2. **二进制被外层标签包裹时变 base64** — `processTags` 是字符串拼接模型，HTTP body 只能是字符串
3. **CSP 允许 `unsafe-eval`** — `new AsyncFunction` 执行用户脚本必需
4. **script 标签无沙箱** — 用户主动编写的本地脚本，等同本地执行 Node
5. **停止是"平滑"的** — 当前整组跑完才停，避免丢状态
6. **副组失败用原包重试** — 重算标签可能得到不同结果（时间戳等），必须用同一包
7. **每轮从 `getProjectSnapshot` 读** — 为了让 op 累积生效（5→6→7→8）
8. **`updateOpTags` 用占位符 `\x00OP{n}\x00`** — 防止新标签被再次匹配
9. **`sanitizeContent` 对 JSON 紧凑化但不删非 JSON 内部换行** — PEM 私钥、多行签名原文需要保留
10. **预检的"警告"是软提醒** — env 未定义可能是设计上想用默认值，不阻断执行
11. **区间状态只在组详情页的监控 Modal 里展示** — 执行日志面板职责是"任务/日志"，不塞区间状态

## 明确不做的事（避免重复提议）

| 提议 | 为什么不做 |
|---|---|
| 做抓包 / 改包重放 / 单请求 fuzz | Burp 已经最强，抢不过 |
| 请求组模板 | 就是"复制组"，没新能力，用户否了 |
| 请求替换保留标签 | HAR 里是密文，diff 无法定位标签边界 |
| 自动打标签规则表 | env 引用已经解决核心痛点 |
| 业务流流程图 / 依赖图可视化 | 改动大，实际需求弱 |
| 参数矩阵批量执行 | 没这个需求 |
| 插件机制 / 热加载 | 个人工具阶段无意义 |
| 把脚本/算法/环境变量再包一层"复用" | 本来就全局共享，已经可复用 |

## 已知限制（功能未做，不是缺陷）

- 无断点调试（只能跑整组或单测副组）
- 无执行历史持久化（日志在内存，关应用会丢）
- 无 WebSocket / gRPC 支持
- 语法校验不覆盖脚本内部 JS 语法
- 提取规则的解密只能引用全局算法配置（不支持规则内联密钥）
- 无插件/扩展机制

## 一句话总结给未来的我

> 这是一个**针对加密业务流的可回放、可并发、可沉淀的工作台**。标签引擎是字符串模型（二进制只在纯标签 body 时原样透传），执行引擎是快照驱动 + 平滑停止 + 多任务并发。**存储全本地，不联网。不做抓包。**
